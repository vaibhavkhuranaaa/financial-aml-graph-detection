# Signal Ledger 1.3.0

## Product

1.3.0 replaces the rules engine and every number measured under it. The fan rules
now count distinct counterparties over a trailing three period window instead of
inside a single review period, which is rules engine version 2. The alert store,
the feature table, the baseline ladder, the challenger, the sensitivity run on the
low prevalence variant and the published triage artifact are all rebuilt from the
same source file under the same verified checksum.

The interface is unchanged. What changed is the population it reads.

## Why

Decision 0006 recorded that the fan rules require a counterparty count no injected
attempt reaches on a single day, and decision 0013 measured the cost: of 337
laundering attempts live in the evaluation window, the rules surface 25, so 92.6
percent of the loss happens before any ordering exists. The suspicion was that the
single day window caused it. A fan spread over three days is still a fan, and a
rule that can only see one day cannot see it.

## The answer is no

At a held alert volume, the wider window surfaces exactly what the narrow one did.

| | Engine 1 | Engine 2 |
| --- | --- | --- |
| Window | 1 period | 3 periods |
| Fan minima | 12 | 18 |
| Alerts per period | 917.1 | 791.2 |
| Attempts live | 337 | 337 |
| Attempts surfaced | 25 | 25 |

Widening the window at the old threshold does surface more, 49 of 337, but it
raises volume to 1,188.5 alerts per period, outside the accepted band of 640 to
960. Holding volume is what the parameterisation rule requires, so the minima rose
to 18, and the gain vanished. The full sensitivity table is in decision record
0014, including two in band rows that surface more than the shipped parameter set.
Neither was taken, because attempts surfaced is computed from the label, and
choosing parameters by it is choosing parameters against the label.

The bound is not a property of the window. It is a property of how small the
injected attempts are against any threshold that holds a workable alert volume.

## What the numbers did

The population is smaller and carries a higher base rate: 4,961 alerts and 204
true positives, against 5,715 and 223. Every ordering improves.

| Ordering | Engine 1 | Engine 2 |
| --- | --- | --- |
| B0 random | 0.0465 | 0.0692 |
| B1 chronological | 0.1134 | 0.1417 |
| B2 amount descending | 0.1361 | 0.1531 |
| B3 rules only priority | 0.1156 | 0.1508 |
| C1 learned ranker | 0.1678 | 0.1905 |

B2 is still the strongest rung on HI-Small and still the rung to beat. C1's lift
over it is 1.2444, interval 1.1460 to 1.3359, against a ship gate of 1.3.

**No model ships.** That is the second engine version to reach the same verdict.

On the low prevalence variant the negative is now stronger. B1 chronological is
the strongest rung there at 0.1610, ahead of B2 at 0.1406. C1 reaches 0.1723, a
lift of 1.0704 over B1 with an interval of 0.9139 to 1.2441, and that interval
contains one. On LI-Small under this engine the learned ranker is not
distinguishable from ordering the queue by arrival time.

## The published artifact

The triage artifact is rebuilt: 623 alerts for review period 2022-09-07 rather
than 749, and 25 true positive alerts rather than 30. Its digest moves to
`0cadbdea` and the pin in `src/app.py` moves with it in the same change, as
decision 0012 requires.

Its distribution decision was approved again rather than carried across. The
source file, its checksum, the variant, the review period and the publication
conditions are all unchanged, but the alert population it is drawn from is not, and
a slice drawn from a different population is a different slice.

## Verification

The full test suite passes, ruff is clean, the frontend lints and builds, and both
arms of the release verifier pass. Both browser journeys were run end to end
against a served build. The leakage gate passes on the rebuilt feature table, and
its own test still proves it fails when a feature reads a transaction at or after
the cutoff.

## Closed

The roadmap note in decision 0006 is closed. Widening the fan window was the one
outstanding change that targeted the measurement bounding every other number in
this project. It was made, it was measured, and it did not move it.
